# Predecessor runtime qualification

The first-demo archive checker verifies all six pinned C4Z hashes and reports
each source and candidate declaration. Its inventory includes XML commands and
parameters, events, variables, conditionals, bindings and classes, proxy IDs,
actions, property types and choices, and native capability declarations. It
records whether a default exists without exporting its value. The original BP
Light `commands.lua` from the source commit in provenance matches the pinned
release member byte for byte. Light 1 and Switch 107 are from the same prototype
repository. The other prototype repositories supply Coordinator 114 and HA
Gesture Bridge 0.1.2. [Package pins](../../provenance/first-demo-baselines.json)
·
[Original BP Light source](https://github.com/bphillips09/Control4-HA-Light/tree/888f0b76cafaba3101ccd962829c5c6da5937c97)
·

### Shared dispatcher and programming details

The BP child packages use the Base dispatcher for property changes, Action
arguments, UI requests, proxy packets and dynamic command parameter lists.
`Entity ID` updates the `ENTITY_ID` variable and requests a snapshot. `REFRESH`
requests a new snapshot for the same selection. The generic Base sensor-type and
polling helpers are bundled library code. The Light and Switch contracts use
authenticated reads and scoped pushed feedback. The retained legacy packet test
uses the archived Base dispatcher and actual original family commands.
[Legacy-family harness](../../lab/verify_legacy_families.lua)

The original BP Light publishes `DYNAMIC_CAPABILITIES_CHANGED`,
`EXTRAS_SETUP_CHANGED` and `EXTRAS_STATE_CHANGED` to its Light V2 proxy. The
candidate exercises capability refresh, effect setup and selected-effect
feedback as part of Light adapter qualification. Explicit color while Off keeps
the load Off, as approved for the suite.
[Light adapter tests](../../test/test_ha_light_adapter.lua)

The prototype Switch uses `SelectDevice`, `Refresh_Entities` and the selection
and operation-mode properties. The prototype Light exposes the same selection
and refresh tasks with `SelectDevice` and `RefreshEntities`, plus
`RefreshLEDFeedback`, native level/ramp commands and LED palette parameter
lists. Dynamic gesture event IDs are keyed by control source, button and action.
Device Setup verifies selection and retry for both families. The gesture tests
verify that retired event IDs cannot be reassigned, including when the order of
physical buttons changes.
[Device Setup tests](../../test/test_ha_device_setup.lua) ·
[Gesture identity tests](../../test/test_ha_gestures.lua)
